# CARNET DE PARIS

Учебный проект для задания «Интерактивная панель управления UI-компонентами».

## Концепция

**CARNET DE PARIS** — личный интерактивный блокнот в эстетике винтажного французского журнала: старая бумага, тонкие линии, архивная композиция, небольшие подписи и функциональные виджеты.

## Функции

- Динамическое добавление и удаление виджетов.
- Сворачивание и разворачивание каждого виджета.
- Независимое состояние каждого экземпляра виджета.
- ToDo-виджет: добавление, удаление и отметка задач.
- Quote-виджет: случайные цитаты и обновление.
- Weather-виджет: реальные данные погоды для Парижа из Open-Meteo.
- Hacker News-виджет: популярные истории из официального Hacker News API.
- Состояния API: загрузка, успешный результат, пустой ответ и ошибка.
- Отмена устаревших запросов через `AbortController`.
- Доступность: семантическая разметка, видимый фокус, `aria-live`, понятные подписи кнопок.
- Редактор композиции: перетаскивание, изменение размера, управление слоями, закрепление и удаление элементов.
- Добавление собственных изображений и текстовых фрагментов.
- Управление выбранным элементом клавиатурой: Enter/Space для выбора, стрелки для перемещения, Shift + стрелка для ускоренного перемещения.
- Отдельное сохранение раскладки для мобильного и широкого экранов.

## Назначение классов

- `UIComponent` — базовый класс виджета. Создает общую оболочку, заголовок, кнопки свернуть/закрыть, хранит обработчики и очистки ресурсов.
- `Dashboard` — управляет коллекцией активных виджетов, добавляет и удаляет экземпляры, использует реестр классов.
- `ToDoWidget` — хранит массив задач внутри экземпляра и управляет списком дел.
- `QuoteWidget` — хранит массив цитат и текущее состояние выбранной цитаты.
- `WeatherWidget` — загружает текущую погоду в Париже через Open-Meteo.
- `HackerNewsWidget` — загружает популярные истории Hacker News ограниченным числом запросов.

## Использованные принципы ООП

- **Инкапсуляция:** состояние задач, цитат и API-запросов хранится внутри соответствующих классов.
- **Наследование:** все виджеты наследуются от `UIComponent`.
- **Полиморфизм:** каждый виджет по-своему реализует `render()`, но используется Dashboard одинаково.
- **SRP:** каждый класс отвечает за свою часть логики.

## API

### Open-Meteo

Документация: https://open-meteo.com/en/docs

Используется endpoint:

```text
https://api.open-meteo.com/v1/forecast
```

Параметры:

- `latitude=48.8566`
- `longitude=2.3522`
- `current=temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m`
- `timezone=Europe/Paris`

API не требует секретного ключа.

### Hacker News API

Документация: https://github.com/HackerNews/API

Используются endpoints:

```text
https://hacker-news.firebaseio.com/v0/topstories.json
https://hacker-news.firebaseio.com/v0/item/{id}.json
```

API не требует секретного ключа. Виджет показывает около 5 историй и проверяет URL перед созданием ссылок.

## Локальный запуск

Проект нужно запускать через локальный HTTP-сервер, потому что используются ES6 Modules.

Вариант через Python:

```bash
python3 -m http.server 8000
```

Затем открыть:

```text
http://localhost:8000
```

Также подойдет VS Code Live Server.

## Проверка API-виджетов

1. Откройте страницу через локальный сервер.
2. Дождитесь загрузки виджета `Weather / Погода`.
3. Нажмите `Refresh / обновить` и проверьте повторную загрузку.
4. Добавьте `News / хроника` через панель управления.
5. Дождитесь загрузки историй Hacker News.
6. Нажмите `Reload / обновить` и проверьте повторную загрузку.
7. Закройте API-виджет во время загрузки: незавершенный запрос должен быть отменен.

## Обработка ошибок и ограничения

- Если API недоступен, виджет показывает сообщение об ошибке и кнопку повтора.
- Если API возвращает пустые данные, показывается отдельное пустое состояние.
- Устаревшие запросы не должны перезаписывать более свежий результат.
- Внешние данные вставляются через `textContent` и созданные DOM-элементы, а не через `innerHTML`.
- Для Hacker News разрешаются только ссылки с протоколом `http` или `https`; иначе используется ссылка на страницу истории на Hacker News.

## Редактирование арт-архива

- Архивные изображения и типографические фрагменты можно перетаскивать мышью в пределах композиции.
- Выберите элемент, чтобы изменить его порядок наложения, закрепить или удалить.
- Добавляйте собственные изображения и текст через панель редактора.
- Элементы доступны для выбора с клавиатуры; Enter или Space выбирает сфокусированный элемент. Выбранный элемент можно перемещать стрелками клавиатуры; `Shift` + стрелка перемещает быстрее.
- Раскладка, координаты, размеры, порядок слоёв и закрепление сохраняются в `localStorage`. Для широкого и мобильного экранов используются отдельные профили раскладки.
- Пользовательские изображения сохраняются как data URL в локальном хранилище браузера; размер хранилища ограничен браузером. Если сохранение не удаётся, уменьшите размер изображения.
- Кнопка сброса восстанавливает начальную раскладку и удаляет добавленные пользовательские элементы.

Редактор предназначен для локального использования в одном браузере. Сохранённая композиция не синхронизируется между устройствами.


## Адаптивность и проверка

- На ширине до 760 px панель редактора и кнопки виджетов перестраиваются в компактную сетку, карточки ограничиваются шириной экрана, а текст переносится без горизонтального переполнения.
- На мобильном экране используется отдельный профиль расположения, чтобы координаты, сохранённые для широкого экрана, не переносились напрямую на узкий экран. Начальная мобильная композиция раскладывает элементы в более узкую вертикальную область; её можно редактировать независимо.
- При изменении размера окна и переходе через breakpoint страница перезагружается для применения соответствующего профиля раскладки.
- Проверка синтаксиса JavaScript выполняется командой `node --check` для модулей. Сетевые запросы к Open-Meteo и Hacker News требуют доступа к интернету; если сеть/API недоступны, виджет должен показывать состояние ошибки и кнопку повтора.
- Перед сдачей необходимо вручную проверить состояния `loading`, `success`, `empty` и `error` у обоих API-виджетов в браузере. Чтобы проверить `empty` и `error`, можно временно использовать тестовый ответ/блокировку запросов в DevTools, а затем удалить тестовые изменения. Не сдавайте проект с имитацией данных вместо реальных API-запросов.
- Фактическая доступность API зависит от сети и настроек браузера. В README не следует считать проверку реальных API завершённой, пока она не выполнена в браузере с доступом к интернету.
